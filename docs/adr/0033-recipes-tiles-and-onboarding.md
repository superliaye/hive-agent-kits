# Recipes, Tiles, and Onboarding

status: proposed
relates-to: ADR-0024, ADR-0026, ADR-0029, ADR-0031, ADR-0032

## What this ADR records

Hive syncs, lists, and distributes agent capability Sources of every common
shape, not only Sources written in Hive's capability format. A user picks a
known repository from a shelf of **Tiles**, or pastes any repository link. Hive
then installs and uninstalls what that repository ships, on Claude Code and
Codex, the way the repository tells a user to do it by hand.

Three repositories show the roles:

- **my-agent-kits**: a personal capability kit that holds working and experimental
  Capabilities.
- **yestack**: a shared plugin with a high bar. Content goes there only when its
  owner promotes it.
- **hive-agent-kits**: the app that syncs, lists, and distributes Sources.

## Decision

- **A Recipe turns a Source into Capabilities.** At Sync, Hive tries its Recipes
  in a fixed order and uses the first that recognizes the tree:
  1. **Capability kit**: the tree has `capabilities/` (ADR-0024).
  2. **Plugin marketplace for both CLIs**: Claude Code and Codex marketplace files
     that list plugins (ADR-0031). Each plugin installs and uninstalls with each
     CLI's plugin commands (ADR-0032).
  3. **Published skills**: skill folders found the way `npx skills add` finds them.
     A `SKILL.md` at the root is one skill. Otherwise the search covers the root's
     children, `skills/` and its curated folders, the agent project skill folders,
     and the skill paths a Claude marketplace declares. If those hold none, a
     deeper search runs. A skill needs a `name` and `description`, and a skill
     marked `metadata.internal` is skipped. Hive deploys each skill natively, as
     it deploys a kit's skills, so no external installer runs.
  4. **Claude-only plugin marketplace** with no published skills.

  A pattern for both CLIs wins over a Claude-only form of the same content, so a
  repository that ships skills and a Claude-only marketplace serves Codex too. A
  tree no Recipe recognizes is reported as not recognized.
- **Generic patterns apply to every Source; repo-specific recipes only to
  Tiles.** A repo-specific recipe covers a repository no pattern fits, such as
  one whose skills are generated by its own `./setup --host <cli>`. Such a recipe
  may run that repository's scripts, so only Tiles can carry one: Onboarding
  reviews the recipe, and Hive ships it. A pasted link gets the generic patterns
  only, and they never run repository code.
- **The Recipe sets the Selection unit.** A capability kit and a collection of
  independent skills let the user pick Capabilities. A plugin installs whole, as
  its CLI does. A repo-specific recipe installs the Source whole. A Tile may
  narrow a collection to whole when its skills depend on each other.
- **Tiles are curated Sources shipped with Hive.** A Tile records a Source Locator,
  a label and description, its Recipe, and its Selection unit. The Starter Source
  is the first Tile. Selecting a Tile adds the Source. Tiles track the
  repository's default branch, like any git Source.
- **Onboarding is a development step in this repository.** For a new repository,
  Onboarding reads the install and uninstall steps its documentation recommends
  for each CLI. It matches them to a generic pattern, generalizes a new pattern
  when the shape is common, or writes a repo-specific recipe. It verifies install
  and uninstall on each CLI in throwaway homes, then adds the Tile with a test that
  pins which Recipe recognizes the repository. End users never run Onboarding.
- **Kits stop wrapping upstream repositories.** A bundle or plugin pointer in a
  kit that only wraps an upstream repository moves to a Tile. The bundle kind
  stays in the capability format for kits that still use it (ADR-0026).

## Trade-offs

- Published-skills discovery copies the `skills` CLI's rules, which can change
  between its versions. Each Tile's test catches a drift that affects that Tile.
- Native skill deploy skips the external installer, so a step the installer adds
  beyond copying folders is lost. Onboarding finds such repositories, and they
  get a repo-specific recipe.
- Tracking the default branch means a Tile changes when its upstream changes.
  Running a repo-specific recipe's scripts from a moving branch trusts the
  upstream with each Sync.
- An unrecognized pasted link fails at Sync with a reason rather than guessing.
